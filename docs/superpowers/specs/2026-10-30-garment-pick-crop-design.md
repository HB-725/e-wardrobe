# 照片里选单品 + 自由裁剪 + 重新生成可调 设计

状态：用户已确认按推荐方案做（2026-10-30）。

## 要解决的问题

1. 一张穿搭照 / 全身照里有多件衣服时，App 只会挑最显眼的一件生成商品图，用户没法指定要录哪件，也没法一次录多件。
2. 没有裁剪：衣服在照片里很小（截图带黑边、全身照里的鞋）时，发给 AI 的图里细节太少，生成质量差。
3. 重新生成时什么都不能调：不能换模型、换画质，不能告诉 AI 哪里不对；在确认页改了品类再重新生成，用的还是旧品类（表单没先保存）。

## 已定的决定

- 一张照片可以一次选多件，每件各成一个单品。
- 识别在后台做，在确认页选（不在导入时当场选，批量导入保持快）。
- 检测方案：合并进现有的识别调用（方案 1 加强版）。这一期只用 OpenAI；接口按「识别模型」走现有路由，以后接 Gemini 不改流程。
- 重新生成面板里可以换模型、换画质、写补充要求。
- 试衣间的生图面板等用户选定 F1–F6 布局后再做，这一期不动试衣间。

## 用户流程

### 导入后（后台）

照片照常马上保存（原图长边上限由 1600 提到 2048，给裁剪留细节）。商品图任务的第一步「识别」改为：找出照片里每件衣服的位置框和名称、品类、颜色等。

- **0 件**：和现在一样，按整张照片生成（现在的识别结果里有「是不是衣服」，但 App 没用它，这一期也不改）。
- **1 件**：按框裁剪（四周各留 6%），框占整张照片 80% 以上就不裁。用裁好的图生成商品图。
- **2 件以上**：不生成商品图（不花生图的钱），单品进入新状态「待选择」，出现在确认页。
- **已在衣橱里的单品换照片**、**带吊牌照片的单品**：不进入「待选择」，自动取和单品品类相同的那件（没有就取最大的那件）裁剪后生成。

### 确认页：待选择

- 照片铺满宽度，每件识别出的衣服中心有白点，选中的显示框。
- 下面一排标签：「黑色T恤 · 上衣」「灰色卫裤 · 下装」……点白点或标签都能选 / 取消，可多选。
- 选中的标签上有「调整」，打开全屏裁剪页微调这件的框。
- 「＋ 自己框一件」：打开全屏裁剪页画一个新框。
- 底部：「全不要」（删掉这张照片）和「录入 N 件 · 约 $x」。确认后每件变成一个单品，用自己的裁剪图生成商品图；自己画的框，或框改动很大（和原框重叠不到 70%）的，先对裁剪图单独识别一次名称、品类、颜色。

### 全屏裁剪页

整张照片 + 一个框：拖四个角改大小，拖框内部移动。完成 / 取消。只做自由矩形，不做旋转、不锁比例。

用在三处：待选择里调整某件的框、自己框一件、重新生成面板里的「调整框选」。

### 重新生成面板

确认页和单品详情页点「重新生成」都弹同一个面板：

- **调整框选**：打开裁剪页，在来源照片上重新框（没有来源照片的老单品就在它自己的原图上框）。保存后原图换成新裁剪图。
- **模型**：列出各 Key 能用的生图模型，每行标这次约多少钱；默认选中当前商品图用的模型。
- **画质**：低 / 中 / 高，只在所选模型支持时显示。
- **补充要求**：输入框 + 快捷项（颜色更浅、颜色更深、保留 logo、保留面料纹理、拉链 / 纽扣颜色不对），点快捷项追加进输入框。只用于这一次。
- **以后商品图都用这个**：勾上则把所选模型设为商品图的路由，所选画质设为商品图画质。
- 按钮：「重新生成 · 约 $x」。

点按钮前先保存确认页表单里改过的品类、名称、颜色；颜色名改了就清掉自动测的颜色值。

### 不用 AI 时

「只存原图」也能先裁剪：裁剪在手机上完成，不调 AI。

## 数据

`items` 表新增三列（迁移一次）：

| 列 | 含义 |
|---|---|
| `source_uri` | 整张来源照片；从同一张照片录入的几件共用。没裁剪过为 null |
| `crop` | 在来源照片上的框，JSON `{x,y,w,h}`，0–1 相对坐标；没裁剪为 null |
| `detections` | 只在「待选择」时有：识别结果数组，每项 `{box, selected, manual, edited, name, slot, subcategory, colorName, colorHex, seasons, brand, size, material}` |

- `ItemStatus` 新增 `'pick'`。`original_uri` 仍是「发给 AI 的那张图」（裁剪后的文件），其余界面不用改。
- 「待选择」单品的 `original_uri` 是整张照片；确认后它的行被删除，照片文件留给子单品作 `source_uri`。
- 删除单品时，`source_uri` 只在没有别的单品引用时才删文件；孤儿图片清理把 `source_uri` 算作引用。
- 备份：`source_uri` 归入 original 文件夹，和其他图片一样导出、恢复。
- 设置 `ai`：新增可选 `catalogQuality`（低 / 中 / 高）。在面板里勾了「以后都用」时写入；在「我的 → 画质」改档位时清掉。最后一次设置的生效。

## AI

- **识别**（`AUTOFILL_*`）：schema 改为 `garments: [{ box_2d: [ymin, xmin, ymax, xmax]（0–1000 整数）, name, slot, …原有字段 }]`。提示词写明：只列人身上穿戴的或照片主体；货架、背景、镜子里重复出现的不算；外套敞开时里面的上衣单独算。走现有 `vision('catalog')` 路由，OpenAI / Gemini 都能用。
- **框的准确度**：OpenAI 小模型框偏粗。实现时用几张真实照片对比现有识别模型（gpt-5.4-nano / gpt-5.4-mini 等），记录框的偏差和价格，再定默认。
- **单件再识别**：对裁剪图调一次原来那种单件识别（不要框）。
- **生成**：`catalogPrompt` 加可选「补充要求」，放在规则之后：主人对这件衣服的说明，照做。任务参数新增 `model`（指定 Key + 模型）、`quality`、`hint`；指定的模型不可用时按现有逻辑换下一个。
- **裁剪**：`ImageStore` 新增 `crop(uri, box, folder)`：原生用 expo-image-manipulator，网页用 canvas，测试用内存实现。

## 出错时

- 识别失败：和现在一样重试 / 暂停队列。
- 「待选择」时网络断了：不影响，选择和裁剪都在本地；确认后的生成任务照常排队。
- 识别返回的框越界或宽高为 0：夹到照片范围内；还不行就丢掉这个框。
- 框面积不到照片 0.5% 的丢掉（多半是误识别的小物件）；丢完剩 0 件就按整张照片走。

## 测试

- 框的计算（0–1000 转 0–1、留边、夹边、面积、重叠率）：纯函数单测。
- 引擎：1 件自动裁剪；多件进入「待选择」且不花生图的钱；已在衣橱的单品换照片取同品类那件；重新生成带 `model` / `quality` / `hint` 时请求里确实用了它们。
- 动作：确认 N 件生成 N 个单品、共用 `source_uri`；删到最后一件才删来源照片；保存表单后再重新生成用的是新品类。
- 备份：`source_uri` 往返。
- 真实 API（需要 Key，默认跳过）：一张两件衣服的照片能识别出两件并给出合理的框。
- 模拟器上走一遍：导入穿搭照 → 选两件 → 调框 → 录入；重新生成面板换模型 + 补充要求。
