# Google Play 上架资料

包名 `app.ewardrobe`，应用名「衣橱」。这里是填 Play 管理中心需要的文字和答案；截图和 AAB 不在仓库里（见最后一节）。

## 1. 商品详情

**应用名称**（30 字以内）：衣橱

**简短说明**（80 字以内）：
拍下衣服自动生成商品图，在自己的形象上试穿搭配，记录每天穿了什么。数据只存在手机里。

**完整说明**：

> 衣橱是一个只存在你手机里的电子衣橱。
>
> • 录入衣服：拍一张或从相册批量导入，AI 自动抠图生成统一的商品图，并认出颜色、季节、品牌、尺码（拍吊牌更准）。也可以从 Excel 导入已有的清单。
> • 试衣间：用 3 张全身照建立你的个人形象，把衣服搭在自己身上看效果，可以转到背面；满意的组合存成穿搭。
> • 今天穿什么：优先推荐很久没穿的搭配，一键记录；拍一张镜子照片，自动认出穿了哪几件。
> • 穿搭日历和统计：每件衣服穿过几次、每次成本多少、多久没穿，帮你发现闲置。
> • 真人大片：选一个场景，把今天的搭配拍成一张照片。
>
> 隐私：没有账号、没有服务器、没有广告和统计。所有照片和数据只保存在你的手机上，可以导出 Excel 或完整备份。AI 功能使用你自己的 OpenAI API Key，直接从手机发送给 OpenAI，第一次发送照片前会征得你的同意；费用由你的 OpenAI 账户按量支付（录入一件约 $0.01–0.02），可以设每月上限。
>
> 不填 API Key 也能用：手动录入、Excel 导入、搭配、记录和统计都不需要 AI。

## 2. 应用内容（App content）

### 数据安全（Data safety）

| 问题 | 答案 |
| --- | --- |
| 是否收集或分享所需的用户数据类型 | 是 |
| 数据传输是否加密 | 是（只走 HTTPS 到 api.openai.com） |
| 用户能否请求删除数据 | 是：「我的 → 永久删除我的全部数据」，或卸载。没有账号，数据不在我们这里 |

数据类型（保守填法：发送给 OpenAI 的都算「收集」和「分享」；可选、用于应用功能、不用于广告）：

| 数据类型 | 收集 | 分享 | 必需 / 可选 | 用途 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 照片和视频 → 照片 | 是 | 是（OpenAI） | 可选 | 应用功能 | 衣服、吊牌、镜子照片和全身照，用户使用 AI 功能且同意后才发送 |
| 个人信息 → 其他信息 | 是 | 是（OpenAI） | 可选 | 应用功能 | 建立形象时的身高、体重、体型 |

不选「临时处理」：OpenAI 可能保留 API 数据最多 30 天用于滥用监测。衣橱里的单品、穿搭、记录、统计都只在手机上，不算收集。
API Key 只用于向 OpenAI 认证，不是 Play 列出的数据类型。

### 内容分级（IARC 问卷）

- 类别选「实用工具 / 效率 / 其他」类问卷。暴力、性、粗话、毒品、赌博：都选否。
- 用户之间能否互动或分享内容：否（没有社交功能；分享图片走系统分享）。
- 是否分享用户位置：否。是否可购买数字商品：否。
- 预计分级：所有人 / 3+（Google Play 可能因为 AI 生成图片给出更高分级，按问卷结果即可）。

### 目标受众

建议只选 **18 岁及以上**（隐私政策写明不面向 13 岁以下；只选成年人可以避开家庭政策的额外要求）。

### AI 生成内容

Play 要求生成式 AI 应用提供举报入口：App 内「我的 → 关于 → 举报不当的 AI 生成内容」已提供（说明举报渠道是 GitHub Issues 或商店页留言）。提示词禁止生成未提供的衣物，输入只来自用户自己的照片。

### 应用访问权限（App access）

选「部分功能受限」，说明：
> AI 功能（生成商品图、个人形象、上身效果、镜子识别、真人大片）需要用户自己的 OpenAI API Key，在「我的 → 我的 API Key」填写。没有 Key 时，手动录入（拍照 → 只存原图）、Excel 导入、衣橱、搭配、日历、统计、备份都可以使用。

如果审核要求可测试 AI，需要提供一个有额度、设了很低每月上限的测试 Key（不要写进代码或仓库）。

### 广告 / 金融 / 健康 / 政府 / 新闻

无广告；其他都选否。

- 不申请读取相册（照片选择器和保存到相册不需要），不申请位置、通讯录、麦克风。

## 3. 发布步骤

1. **签名**：用 `ewardrobe-release.jks`（你保管的那份，不在仓库里）打 AAB，加入 Play App Signing 时选「使用 Google 生成的应用签名密钥」，这份 keystore 就是上传密钥。丢了上传密钥可以在 Play 后台申请重置；但已经直接装 APK 的用户只能用这份密钥更新。
2. **打包**：`cd app && BUNDLE=1 EW_SIGNING_ENV=path/to/signing.env scripts/build-apk.sh`，产物 `app/android/app/build/outputs/bundle/release/app-release.aab`（arm64-v8a + armeabi-v7a）。每次上传前把 `app.json` 的 `version` 和 `android.versionCode` 加一。
3. **测试轨道**：先上「内部测试」自己装一遍。**2023 年 11 月之后注册的个人开发者账号**，正式发布前必须做封闭测试：至少 12 名测试者连续参与 14 天，之后才能申请正式版。
4. **商店截图**：手机截图至少 2 张，最长边不超过最短边 2 倍。用网页预览生成 1080×1920：
   `cd app && npx expo export --platform web && node scripts/web-shots/serve.js dist scripts/web-shots/demo &`，再 `VW=360 VH=640 DPR=3 node scripts/web-shots/shoot.js <输出目录>`，建议用 today、wardrobe、fitting-collage、outfits、calendar、review。演示图片都是 AI 生成的样例人物。
   另外需要 512×512 图标（`app/assets/icon.png` 缩放）和 1024×500 置顶大图。
5. **目标 API**：targetSdk 36，满足 Play 当前要求。
